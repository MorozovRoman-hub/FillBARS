# Контрольная точка 5.2.9 — дополнительные бланки

## Реализовано

- Перенесено получение ABO/Rh из штатной формы `ArmPatientsInDep/patients_information`, включая скрытое открытие и вызов `getBloodgroupe`. Контекст задаётся по текущей истории болезни; временная форма закрывается, ожидание ограничено 8 секундами.
- В заявке на кровь и протоколе трансфузии подставляются найденные ABO/Rh. Пустое значение не превращается в выбранную группу.
- Добавлен список «Другие бланки»: выписка для военнослужащих, заключение ВК, направление 057/у-04, онкологическое извещение, заявка ТМК.
- Поля ФИО, даты рождения, паспорта, СНИЛС, полиса и адреса читаются из открытой `.persmedcard_edit`; диагноз и МКБ — из истории болезни. Медорганизация поддерживает подписи «ЛПУ» и «МО».
- Паспорт и адрес сверяются с историей по AGENT; при недоступных идентификаторах нужны совпадение ФИО и даты рождения. Разные кадры не склеиваются в одного пациента. Смена пациента во время ожидания блокирует результат.
- Адрес регистрации отделён от фактического; учитывается `ADDR_REAL_EQ_REG`.
- Все поля редактируются перед выгрузкой. Временный пакет данных удаляется после чтения; старые пакеты очищаются при следующем открытии. В диагностике нет паспортов/адресов.

## Форматы и шаблоны

Word создаётся на основе копии исходного OOXML-пакета, не HTML с расширением DOC. Повторные примеры пациентов удалены, личные данные и выборы из образцов заменены пустыми полями. Исходные документы пользователя не изменены и не включены в репозиторий.

ТМК — исходный XLSX с заполнением только C3–C30 по карте полей. Стили, объединения, проверки данных, формулы, остальные части книги и настройки печати сохраняются. Формульные ячейки не разрешается заменять. Даты записываются числом Excel; номера полиса и СНИЛС — текстом. В предоставленном образце обычных формульных ячеек не обнаружено; сохранение формул проверено также на тестовой добавленной формуле.

Браузер показывает предпросмотр содержания. Эталон точного печатного оформления — скачанный файл Office. Бланки воспроизводят предоставленные образцы; актуальность нормативных реквизитов не проверялась.

## Проверено

- Автотесты Office-пакетов, XML-экранирования, исходных частей, Excel-формул и дат, чтения карточки, разных адресов, несовпадающих пациентов, временного окна ABO/Rh, редактора и удаления временного пакета.
- Четыре DOCX открыты установленным Microsoft Word и визуально проверены после PDF-экспорта: каждый бланк — одна страница на синтетическом примере.
- XLSX открыт установленным Microsoft Excel, проверены заполненная фамилия и дата; PDF — одна страница, исходная таблица сохранена.
- В живой карточке БАРС подтверждено наличие нужных DOM-полей без изменения медицинских записей.
- Полный последовательный прогон: 141 тест пройден (`node --test --test-concurrency=1 tests/card-*.test.js`), runtime-injection и package-check пройдены. В параллельном прогоне выявлен таймерозависимый тест существующих дневников `позднее наследование...`: иногда событие происходит до проверяемого этапа; в последовательном прогоне проходит. Код дневников в этом патче не менялся.

## Ограничение текущего патча и ручная приёмка

Паспорт и полный адрес пока берутся из **открытой карточки пациента, вкладка «Документы / Адреса»**. Если её не открыть, бланк показывает предупреждение, поля остаются пустыми для ручного ввода. Скрытую загрузку редактирующей карточки не добавляли: она требует отдельного анализа побочных действий БАРС. Группа крови из «Общих сведений» загружается автоматически без ручного открытия этой формы.

Для сквозной проверки нужно перезагрузить расширение из рабочей папки `FillBARS-5.2.8` (версия в manifest теперь 5.2.9), открыть историю и карточку одного пациента, выбрать бланк и проверить реквизиты. Реальное выполнение новой версии через popup пользователем ещё не подтверждено. Изменения не запушены.
