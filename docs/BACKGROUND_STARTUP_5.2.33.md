# Запуск фоновой карточки — 5.2.33

Журнал 5.2.32 показал остановку всех трёх участников группы с кодом
background_loading_card: после появления openWindow в скрытой среде
карточка hosp_history_new не появилась за 30 секунд (cardCount=0).
Итог noWrites=true: осмотры этой группы не создавались.
Причина внутри сервера из исходного журнала однозначно не устанавливается:
запросы getform.php и состояние начальной загрузки ранее не записывались.

В запуске устранены две потенциальные причины:

- Вместо безусловного origin + '/' используется каталог приложения из
  текущего baseURI, с проверкой того же origin и удалением query/hash.
  Поддерживается размещение МИС в подпапке и переход каталога на index.php.
- Наличия функции openWindow недостаточно для готовности. Запуск ожидает
  readyState=complete, основной контейнер _mainContainer, привязку MainDom
  при наличии D3 и завершение native/D3 запросов. Готовность должна сохраняться
  300 мс, затем открывается карточка.

Запрос входа/выбора учреждения и смена документа выделены отдельными ошибками.
В журнале отражаются этап открытия карточки, наличие возвращённого DPage,
уничтожение страницы, числовые счётчики запросов и тип ошибки JavaScript.
Для getform/getdata/getmodule/request добавлены только имена endpoint и HTTP-статусы;
URL, тела запросов, идентификаторы госпитализации и тексты ответов не записываются.
Первая причина отказа группы также попадает в run.code.

Стенд проверяет задержанную инициализацию при уже доступном openWindow,
размещение в подпапке, запрос авторизации, отсутствие записей при неготовой
карточке, изоляцию загрузчика и отсутствие реквизитов в техническом журнале.
Изменения не заменяют отдельный контрольный запуск в рабочем БАРС.
