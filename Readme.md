# FillBARS / МИС БАРС — автоматическое назначение анализов

**FillBARS** — локальное расширение для Chromium/Yandex Browser, которое помогает врачу быстро назначать наборы лабораторных исследований в МИС БАРС и формировать печатный лист назначений.

Версия: **5.1.11**

## Что умеет расширение

- Выбирать профиль назначений и отмечать нужные анализы в форме БАРС.
- По настройке «Срочно» устанавливать CITO для выбранных строк исследований до открытия расписания.
- По отдельной настройке открывать штатное расписание БАРС и подставлять выбранный кабинет для каждой строки услуги.
- Работать со старыми профилями, где профиль был только набором ID анализов.
- Хранить новый профиль как список анализов, лекарственных назначений и диагностических/режимных процедур.
- Печатать двухстраничный HTML-лист назначений на A4.
- Сохранять локальный журнал назначений без ФИО пациента.
- Импортировать и экспортировать настройки одним JSON-файлом.

Расширение не нажимает финальную кнопку записи в БАРС. Ответственность за назначение остаётся за лечащим врачом.

## Установка

1. Откройте страницу расширений браузера:

```text
browser://extensions
```

2. Включите режим разработчика.
3. Нажмите «Загрузить распакованное расширение».
4. Выберите папку проекта, где лежит `manifest.json`.

## Профили назначений

Новая структура профиля:

```json
{
  "analyses": {
    "97829568": true,
    "97830108": true
  },
  "medications": [],
  "procedures": []
}
```

Старые профили вида:

```json
{
  "97829568": true,
  "97830108": true
}
```

автоматически читаются как `analyses`, а при экспорте сохраняются уже в новом формате.

## Как создать профиль с препаратами

1. Откройте popup расширения.
2. Нажмите кнопку с шестерёнкой справа от названия FillBARS.
3. Нажмите «+ Добавить назначение» или «Ред.» у существующего профиля.
4. Во вкладке «Анализы» выберите исследования.
5. Во вкладке «Препараты» найдите препарат в справочнике ЖНВЛП или заполните препарат вручную.
6. Укажите дозу, путь введения, кратность, длительность, режим и комментарий.
7. Нажмите «Добавить препарат в профиль».
8. Во вкладке «Процедуры» добавьте ЭКГ, ЭГДС, УЗИ, колоноскопию, диету, режим или другое назначение.
9. При необходимости измените порядок препаратов и процедур стрелками.
10. Сохраните профиль.

Справочник `drug-catalog-zhvnlp-2025.json` используется только для выбора названия, АТХ, группы и лекарственной формы. Дозу, кратность, путь введения и длительность врач указывает сам.

Если препарата нет в справочнике, его можно добавить вручную и сохранить в пользовательский справочник. Пользовательский справочник хранится локально в браузере и попадает в экспорт настроек.

## Как назначать анализы в БАРС

1. Откройте форму назначения анализов в МИС БАРС.
2. Убедитесь, что отображаются все нужные исследования.
3. В popup выберите профиль.
4. Нажмите «Заполнить форму БАРС».

Версия 5.1.11 распознаёт форму по точному контракту исходников БАРС (`GridGroups` + `GridResearch` + `GridDirline`) и различает два runtime: реальный D3 engine в `page.d3Form` и legacy DForm в `page.form`. Внутренний D3 namespace `Form` читается штатным `execScript`, активная группа — через `getValue('GridGroups')`, а `ALL_RES` запускается одним `D3Api.GridCtrl.activateRow(row, true)`. Готовность подтверждается только после фактического появления нового поколения строк `GridResearch`; затем выбранные исследования проверяются по `GridDirline`.

Для старой логики БАРС используется только часть профиля `analyses`. Препараты и процедуры не передаются на страницу БАРС и нужны для печатного листа и журнала.

### Режим «Кабинеты»

1. В настройках укажите точное название кабинета.
2. Переведите этап выполнения из «Только анализы» в «Кабинеты».
3. Если назначения должны быть срочными, включите опцию «Срочно».
4. Запустите заполнение профиля.

В этом режиме после выбора анализов расширение нажимает штатную кнопку «Назначить». БАРС выполняет `SaveAction` и открывает форму `Lis/Dirline/forms/schedule`; это уже серверное действие БАРС. Кабинеты обрабатываются по стабильному ключу `RN` строки `GridServices`.

В `available_cablabs.frm` окно становится видимым раньше, чем асинхронно загрузятся `DS` и строки `Grid1`. Версия 5.1.11 ждёт их полной отрисовки до пяти секунд, требует единственное точное совпадение названия и только затем выполняет штатную цепочку исходников БАРС: `setThisActivRow(row, true)` → `Form.OnOkButtonClick()`. Закрытый или заменённый справочник не может подтвердиться позднее. Успех сверяется с точным ID выбранной строки после фактического заполнения `ctrlCABLAB` и завершения асинхронного `Form.getRecTime()`. ID и подпись каждого точного clone-control читаются через штатный компонентный API `D3Api.ButtonEditCtrl.getValue/getCaption`: именно он возвращает `keyvalue`, тогда как generic `getControlValue(control)` и legacy `ButtonEdit_GetValue(control)` в живой сборке могут вернуть видимую подпись вместо ID. Name-based API сохранён только как fallback для других сборок БАРС. Если MAIN-runner уничтожен при перерасчёте `Form.getRecTime()`, isolated bridge версии 5.1.11 обнаруживает отсутствие active-lock при всё ещё открытом расписании и запускает только безопасное schedule-only продолжение; завершённый этап повторно не запускается.

Переход после штатной кнопки «Назначить» наблюдается также из изолированного bridge. Если `SaveAction` БАРС уничтожил старый MAIN-контекст, но точная видимая `.form-schedule` уже появилась, service worker один раз возобновляет только этап расписания в том же tab/frame. Повторный клик «Назначить» запрещён активной блокировкой runner; финальная кнопка «Записать» не нажимается.

Закрытие справочника кабинетов само по себе не считается успехом. Если подтверждены не все строки, запуск помечается как частичный и сохраняет причину в диагностическом логе. Финальную кнопку «Записать» в расписании FillBARS не нажимает.

Исходники БАРС показывают, что признак CITO задаётся в строках `GridResearch`/`GridDirline` до открытия расписания; в форме `Lis/Dirline/forms/schedule` отдельного checkbox «Срочно» нет. Версия 5.1.11 после выбора исследований находит соответствующие строки `GridDirline`, переключает их штатный контрол `Cito` пользовательским событием и перечитывает результат через `D3Api.CheckBoxCtrl`. БАРС сохраняет это значение как `IS_CITO` и передаёт его в `SaveAction` как `pnIS_CITO`. Если хотя бы одна выбранная строка отсутствует, контрол недоступен или новое состояние не подтверждено, сценарий останавливается с причиной `cito_selection_incomplete` до кнопки «Назначить»; несрочное назначение вместо срочного не создаётся.

## Как печатать лист назначений

1. В popup выберите профиль назначений.
2. При необходимости измените дату назначения.
3. Оставьте активной страницу пациента в МИС БАРС.
4. Нажмите «Открыть лист назначений».
5. Расширение автоматически прочитает ФИО и дату рождения из активной страницы БАРС и откроет HTML-бланк в отдельной вкладке.
6. Нажмите «Печать».

Печатная форма:

- формат A4 landscape;
- страница 1: «ЛИСТ НАЗНАЧЕНИЙ И ИХ ВЫПОЛНЕНИЕ» с лекарственными назначениями и лечебным питанием;
- шапка страницы содержит пустые поля диагноза, аллергии, номера палаты и номера истории болезни;
- страница 2: оборотная сторона с таблицей «Медицинское вмешательство»: сначала назначенные анализы, затем диагностические и режимные процедуры;
- кнопки печати и закрытия скрываются при печати.

## Локальное хранение

Постоянно хранятся:

- профили;
- анализы в профилях;
- препараты в профилях;
- диагностические, режимные и иные назначения в профилях;
- каталог анализов;
- пользовательский справочник препаратов;
- настройки расширения.

Временный журнал назначений хранится в IndexedDB до 60 дней.

В журнал сохраняются:

- технический ID записи;
- дата создания записи;
- № медицинской карты, автоматически прочитанный из активной страницы БАРС;
- выбранный профиль;
- список лекарственных назначений;
- список процедур и режимных назначений;
- список анализов.

В `fillbars-config.json` добавлены заполненные шаблоны на основании файла `профиля.txt`:

- острый тромбофлебит;
- острый панкреатит;
- острый аппендицит;
- ректальное кровотечение;
- желудочно-кишечное кровотечение.

В журнал не сохраняются:

- ФИО пациента;
- дата рождения.

Если номер медицинской карты не найден на активной странице БАРС, запись в журнал не создаётся.

Автоочистка выполняется при каждом запуске popup: записи старше срока хранения удаляются. В настройках есть кнопка «Очистить журнал сейчас».

### Диагностика запусков

Каждое нажатие «Открыть лабораторию и заполнить» автоматически создаёт локальный технический лог. Хранятся последние 12 запусков: этапы открытия формы, найденный frame, состояния `ALL_RES` и Range, сигнатуры строк, технические ID исследований, результат и причина остановки. События порционно передаются из страницы в service worker и сохраняются в `chrome.storage.local`, поэтому лог продолжает пополняться после закрытия popup.

FillBARS не добавляет в диагностический лог ФИО, номер медицинской карты, дату рождения, адрес или заголовок страницы; сырые сообщения ошибок API также не сохраняются. Лог содержит название выбранного профиля и технические ID исследований, поэтому JSON нужно проверить перед передачей. Кнопка «Диагностика запусков» позволяет выбрать любой из последних запусков, скопировать его или выгрузить отдельным JSON-файлом. Логи можно удалить вручную; наружу они автоматически не отправляются.

## Импорт и экспорт

Кнопка «Экспорт настроек» сохраняет:

- профили в новой структуре;
- активные профили;
- настройки сценария БАРС;
- настройки журнала;
- каталог анализов;
- пользовательский справочник препаратов.

Кнопка «Импорт настроек» загружает JSON обратно в расширение.

## Безопасность

Расширение не отправляет данные на внешние серверы и не подключает внешние библиотеки через CDN. Данные обрабатываются локально внутри браузера.
